---
title: "Update Review"
description: "Submit reviewed extraction results for a document"
---

## Endpoint

```
PUT https://api.documind.cloud/api/v1/review/{document_id}
```

## Authentication

Requires `extractions:write` scope.

## Path Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `document_id` | string (UUID) | Yes | ID of the document whose extraction was reviewed |

## Request Body

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `reviewed_results` | object | Yes | Human-reviewed extraction data |

## Response

```json
{
  "status": "success"
}
```

## Example

```python
response = requests.put(
    f"https://api.documind.cloud/api/v1/review/{document_id}",
    headers={"X-API-Key": API_KEY},
    json={
        "reviewed_results": {
            "invoice_number": "INV-2026-001",
            "total": 1250.00
        }
    }
)
```

## Workflow compatibility

For `review_decision_managed=false` or an absent snapshot, this endpoint preserves the existing legacy approval and result-editing workflow, including reapproval of previously reviewed results. Legacy review booleans and reflagging semantics remain unchanged. It does not enroll a document into managed decisions or create a managed decision event.

For `review_decision_managed=true`, this is a guarded approval adapter. It accepts only managed pending documents with completed technical processing and authorized write scope. It cannot reopen or overwrite a managed terminal decision.

Managed clients that need reliable retry identities should use [Submit Review Decision](/api-reference/review-decision). Unmanaged clients keep their existing PUT integration.
