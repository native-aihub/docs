---
title: "Update Review"
description: "Submit reviewed extraction results for a document"
---

## Endpoint

```
PUT https://api.documind.cloud/api/v1/review/{document_id}
```

## Authentication

Requires `extractions:write` scope.

## Path Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `document_id` | string (UUID) | Yes | ID of the document whose extraction was reviewed |

## Request Body

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `reviewed_results` | object | Yes | Human-reviewed extraction data |

## Response

```json
{
  "status": "success"
}
```

## Example

```python
response = requests.put(
    f"https://api.documind.cloud/api/v1/review/{document_id}",
    headers={"X-API-Key": API_KEY},
    json={
        "reviewed_results": {
            "invoice_number": "INV-2026-001",
            "total": 1250.00
        }
    }
)
```

## Approval compatibility

This endpoint is a guarded approval adapter. It accepts only a pending document with completed technical processing and the caller's organization/project write access. It cannot approve rejected, expired, legacy-reviewed, or not-required records, or bypass state checks.

For client-managed retry identities, use [Submit Review Decision](/api-reference/review-decision) with `decision=approved`, `reason_code=review_approved`, and a UUID idempotency key. The legacy PUT generates its own request identity; a blind retry can return a conflict after the original approval succeeds.
