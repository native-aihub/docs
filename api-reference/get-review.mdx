---
title: "Get Review State"
description: "Read current review state and immutable decision evidence"
---

```http
GET /api/v1/review/{document_id}
```

Requires `extractions:read` and access to the document's organization and project. Send `X-API-Key` and, when using an active project, `X-Project-ID`.

For pending documents, decision fields and `decision` are null. Extraction history, extraction detail, synchronous extraction responses, batch items, and pending summaries also expose review state and metadata. Read this endpoint for the full decision evidence.

Use `GET /api/v1/data/extractions?review_status=pending` for the pending queue. Rejected and expired records retain `needs_review=true` and `is_reviewed=false`; boolean filters do not identify the pending queue.

See [availability](/api-reference/review-capabilities) and [state dispatch](/api/review/polling-pattern). This response records the Documind decision. It does not confirm that your downstream system canceled its work item.

If multiple extraction records share a document identity, this route returns `409`, including records in different projects. Do not automatically choose one record or infer approval from a project-filtered list. Resolve the identity before deciding.
