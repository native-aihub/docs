---
title: "Polling for Reviews"
description: "Wait for explicit decisions without treating rejection or missing state as approval"
---

<Warning>
Explicit review decisions require the review-state migration and a compatible backend deployment. Documentation publication does not enable the feature. Check [review capabilities](/api-reference/review-capabilities) before integrating. For managed documents, missing or unknown `review_status` stops automatic processing. Projects explicitly opt in after customer integrations support terminal decisions. False or absent `review_decision_managed` keeps existing legacy behavior; it never enrolls a document implicitly.
</Warning>

## Select the contract first

Read `review_decision_managed` from the existing extraction response. False or absent preserves your existing legacy processing, polling, editing, and PUT integration. Do not switch that document because its project later opts in. Only new requests explicitly sending `review_contract="decisions_v1"` can become managed, subject to project activation and trusted access. Omitted requests remain legacy, even when other robots in that project adopt the feature. True uses the managed helper below. The helper returns `legacy_policy` if the server says the document is unmanaged; it does not infer a managed approval.

## Poll each known document

Read `GET /api/v1/review/{document_id}` for authoritative state and decision evidence. For approval, retrieve the exact extraction ID from the audit event. For a document without a decision, query extraction history by document ID and require one matching record. Keep the work item identity in your integration. A document disappearing from the pending list does not prove approval.

| `review_status` | Integration action |
| --- | --- |
| `pending` | Wait and poll again. |
| `approved` | Continue only when technical `status=completed`. Use `reviewed_results`; fall back to `results` only if reviewed results are null. An empty object is valid. |
| `rejected`, `expired` | Cancel your downstream work item. Your integration performs cancellation. |
| `not_required` | Use `results` only when technical `status` is `completed`. |
| `legacy_reviewed` | Preserve your existing legacy policy. This is not a new explicit approval. |
| Missing or unknown (managed documents) | Stop automatic processing and check deployment compatibility. |

## Python example

This function returns a named outcome. The caller must handle cancellation, legacy policy, and timeout separately. It never returns extraction data for a rejected, expired, or unknown state.

```python
import time
import requests

def poll_for_review(document_id, api_key, project_id=None, timeout=600):
    base = "https://api.documind.cloud/api/v1"
    headers = {"X-API-Key": api_key}
    if project_id:
        headers["X-Project-ID"] = project_id
    deadline = time.monotonic() + timeout
    interval = 10
    while time.monotonic() < deadline:
        try:
            response = requests.get(
                f"{base}/review/{document_id}", headers=headers, timeout=30
            )
            if response.status_code == 429 or response.status_code >= 500:
                time.sleep(interval)
                interval = min(interval * 2, 60)
                continue
            response.raise_for_status()
        except (requests.Timeout, requests.ConnectionError):
            time.sleep(interval)
            interval = min(interval * 2, 60)
            continue
        review = response.json()
        if review.get("review_decision_managed") is not True:
            return {"outcome": "legacy_policy"}
        state = review.get("review_status")
        if state in ("rejected", "expired"):
            return {"outcome": "cancel", "review_status": state}
        if state == "legacy_reviewed":
            return {"outcome": "legacy_policy", "review_status": state}
        if state == "approved":
            extraction_id = (review.get("decision") or {}).get("extraction_id")
            if not extraction_id:
                raise RuntimeError("Approval evidence unavailable; stop processing")
            response = requests.get(
                f"{base}/data/extractions/{extraction_id}", headers=headers, timeout=30
            )
            response.raise_for_status()
            extraction = response.json()
            if extraction.get("document_id") != document_id or extraction.get("status") != "completed":
                raise RuntimeError("Approved extraction not completed; stop processing")
            results = extraction.get("reviewed_results")
            if results is None:
                results = extraction.get("results")
            if not isinstance(results, dict):
                raise RuntimeError("Approved results unavailable; stop processing")
            return {"outcome": "continue", "results": results}
        if state == "not_required":
            response = requests.get(
                f"{base}/data/extractions", headers=headers,
                params={"document_id": document_id, "limit": 2}, timeout=30
            )
            response.raise_for_status()
            items = response.json().get("items", [])
            if len(items) != 1:
                raise RuntimeError("Document missing or ambiguous; stop processing")
            extraction = items[0]
            if extraction.get("review_status") != "not_required":
                raise RuntimeError("Review state changed; poll again before processing")
            if extraction.get("status") == "completed":
                return {"outcome": "continue", "results": extraction["results"]}
            if extraction.get("status") == "failed":
                raise RuntimeError("Extraction failed; stop processing")
        elif state != "pending":
            raise RuntimeError("Review state unavailable; check compatibility")
        time.sleep(interval)
    return {"outcome": "local_timeout"}

# The API key comes from your application's secret configuration.
# Dispatch explicitly. Do not use result truthiness as proof of approval.
outcome = poll_for_review(document_id, api_key, project_id)
if outcome["outcome"] == "continue":
    process_document(outcome["results"])
elif outcome["outcome"] == "cancel":
    cancel_downstream_work_item(document_id)
elif outcome["outcome"] == "legacy_policy":
    apply_existing_legacy_policy(document_id)
else:
    alert_review_team(document_id)
```

## Polling limits and failures

Use a bounded interval, such as 10?15 seconds, and back off on temporary failures. Respect `Retry-After` when supplied. Stop automatic processing on access errors or unknown state. For multiple documents, apply the same state dispatch to each known document; paginate history if querying a list. Do not poll only the pending queue to detect approval.

A local timeout stops waiting in your process. It does not approve, reject, or expire the document. [Caller-triggered expiry](/api-reference/review-decision#caller-triggered-expiry) is a separate API-key request and requires pending age strictly greater than ten days. There is no scheduler or webhook in this contract.

For `409` on a decision request, refresh state and capabilities. Do not automatically submit a different decision. After an uncertain network failure, retry the exact decision payload with its original idempotency UUID and caller identity.

## Node.js state dispatch

Apply this dispatch after reading authoritative state and its stored extraction. `cancelWorkItem`, `processDocument`, and `applyLegacyPolicy` are functions owned by your integration.

```javascript
async function dispatchReview(review, extraction) {
  if (extraction.review_decision_managed !== true) {
    return applyLegacyPolicy(extraction.document_id);
  }
  switch (review.review_status) {
    case "rejected":
    case "expired":
      return cancelWorkItem(review.document_id);
    case "pending":
      return { outcome: "wait" };
    case "legacy_reviewed":
      return applyLegacyPolicy(review.document_id);
    case "approved": {
      if (extraction.status !== "completed" ||
          extraction.id !== review.decision?.extraction_id ||
          extraction.document_id !== review.document_id) {
        throw new Error("Approval does not match completed extraction");
      }
      const results = extraction.reviewed_results === null
        ? extraction.results : extraction.reviewed_results;
      if (results === undefined) throw new Error("Results unavailable");
      return processDocument(results); // {} is a valid reviewed result.
    }
    case "not_required":
      if (extraction.review_status !== "not_required" || extraction.status !== "completed") {
        return { outcome: "wait_or_technical_failure" };
      }
      return processDocument(extraction.results);
    default:
      throw new Error("Review state unavailable; stop automatic processing");
  }
}
```

## Batch and concurrent polling

Keep a set of document IDs that belong to your workflow. Poll each ID with the same dispatcher and remove it only after recording a named terminal outcome. Cancel rejected/expired work items separately from successful outputs. Bounded concurrency prevents a large batch from exhausting API limits. An empty page or an item absent from a pending queue is not a terminal outcome.

Configure polling interval, local timeout, and maximum backoff per workflow. These settings control your process, not server expiry. Track approved, rejected, expired, legacy-policy, local-timeout, and technical-failure counts separately. Do not log API keys or document contents.
